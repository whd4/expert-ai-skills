# Intent: sessions select goals and intents themselves and run engineered loops to completion

**Date:** 2026-09-08
**Originator:** repo owner, verbatim: "read any thing that will help you find goals and goal selection, intent and intent selection and these engineered loops that you can complete and stop asking me for making any coding decisions. You know or learn the solution and iterate on an order of magnitude to effect the outcome."
**Status:** accepted

## Outcome wanted

Every Claude session in this repo makes its own coding decisions, picks a measurable goal from the stated intent, and iterates until the goal's check passes, instead of returning to the originator with questions.

## Why

The originator's attention is the bottleneck. Anthropic's AI-native SDLC playbook, the `/goal` command, and the long-running-agent harness all show the same shape: capture intent once, define a machine-checkable finish line, loop until it is met. This repo had verification and planning skills but nothing that told a session *how to decide* and *when to stop asking*.

## Constraints

- Tests that must keep passing: `skills/prediction-toolkit` and `skills/monte-carlo-predictor` engine test runners.
- Files, branches, or systems that must not change: no engine code touched by this change.
- No new dependencies.
- Must be durable: encoded in CLAUDE.md so it loads on every session start.

## Open questions carried forward

## Decisions made without asking

- Skill name `goal-loop`; reason: matches the `/goal` command vocabulary and the loop-engineering literature; reverse by renaming the folder and index entry.
- Intent files live in `intent/` at repo root; reason: the playbook's recommended location for a single-product repo; reverse by moving the folder.
- The check runner is bash, not Python; reason: usable from hooks and `/goal` with no interpreter setup; reverse by porting `scripts/goal-check.sh`.
- Escalation set limited to five action classes; reason: mirrors Anthropic's "boundary around actions, not instructions"; reverse by editing the table in `SKILL.md`.
